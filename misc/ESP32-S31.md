# ESP32-S31 (experimental, untested on hardware)

The firmware also builds for the **ESP32-S31-Function-CoreBoard-1** (Gigabit Ethernet with a YT8531 PHY). The port
comes from upstream release 4.0. **Nothing of it has run on an ESP32-S31 in this fork**: only the build is checked.
The ESP32-S31 is a *preview* target of ESP-IDF 6.1 (`idf.py --preview`).

## Build

With the ESP-IDF environment loaded:

```powershell
python tools/build.py --profile s31            # build folder build_s31
```

or by hand:

```powershell
idf.py --preview -B build_s31 -DIDF_TARGET=esp32s31 -D SDKCONFIG=build_s31/sdkconfig `
       -D SDKCONFIG_DEFAULTS="sdkconfig.defaults;config/esp32s31_function_coreboard_1.defaults" build
```

Each build folder has its own `dependencies.lock`: the S31 uses `jef-sure/hd44780` for the LCD (esp-idf-lib's driver
does not declare the S31) and may use newer `led_strip` / `mdns` releases than the P4 build. Both builds share
`managed_components`, so switching between a P4 and an S31 build downloads those components again. Flash with
`idf.py -p COMx flash` from the build folder (16 MB flash); updates over the network (OTE) use the same code as on the P4 (also untested on the S31).

## Wiring

Note: the J2 header numbers on the board's silk screen are not the GPIO numbers.

| Connection                         | S31 GPIO     | J2 pin       |
| ---------------------------------- | ------------ | ------------ |
| GNSS receiver RX (MCU TX)          | 22           | D2           |
| GNSS receiver TX (MCU RX)          | 21           | D1           |
| GNSS PPS input                     | 20           | D0           |
| PTP PPS loopback (nothing wired)   | 23           | D3 (leave free) |
| LCD SDA / SCL (fixed)              | 38 / 39      | 22 / 21      |
| Uptime / restart button            | 40           | 19           |
| Addressable LED on the board       | 60           | 6            |
| Optional KY-016 blue / green / red | 46 / 47 / 48 | 16 / 13 / 14 |

These are the defaults of an S31 build; except for the LCD and Ethernet they are settings on the web page, as on the
P4 (GPIO 0 to 61; GPIO 29 and 41 do not exist). Use 3.3 V signals only; the LCD goes to a 3.3 V power pin, never 5 V.
Reserved by the firmware: Ethernet RGMII and SMI (GPIO 5 to 19), the UART0 console (58, 59) and the LCD bus (38, 39).
The strapping and USB pins of the S31 are not known to the firmware: check the board documentation before you move a
pin.

### Optional TF card reader (SPI)

The board has no TF slot. For the MQTT queue of QoS 1 and 2, a 3.3 V SPI TF reader with a FAT32 card can be connected;
the TF pin settings of the web page are used in SD-SPI mode:

| Reader pin | Setting | Default GPIO |
| ---------- | ------- | ------------ |
| CS         | D3      | 0            |
| MOSI       | CMD     | 1            |
| CLK        | CLK     | 2            |
| MISO       | D0      | 3            |

D1 and D2 are not used (hidden on the page). GPIO 0 and 1 need the optional 32.768 kHz crystal of the board to stay
unpopulated. The reader runs at 4 MHz (short wires); without a usable card the reports wait in RAM as on the P4.

## Differences to the ESP32-P4 build

- Ethernet: RGMII with the YT8531 PHY (RX/TX clock delays and autonegotiation set after the driver start, PHY address
  found on the bus); the status shows 1000 Mbit/s when the link has it.
- PTP PPS loopback: available on every S31 (on the P4 from chip revision 3.0).
- NTP load shedding threshold 8500 requests per second (upstream's value, not measured on the S31).
- Everything else (PPS discipline, PTP clock from the 80 MHz PLL, 16 MHz systimer, NTP, PTP, web admin) is the same code;
  the timing values were measured on the P4 only.
